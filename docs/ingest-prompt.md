# 给其他 agent 的 ingest prompt

让 agent 能访问 Pinakes 源码仓库、目标知识库及论文原文。在仓库根目录工作且已读取 `AGENTS.md` 时，仍可直接使用 `ingest <论文标题 / 链接 / PDF 路径>`；不需要每次粘贴长提示。

切换工具或开始新会话时，可以复制下面的任务提示并替换占位内容。阅读与写作标准统一维护在 [知识库约定 §6](wiki-conventions.md#6-正文写作)，完整录入流程见 [§7](wiki-conventions.md#7-录入流程)。本页是任务入口。

```text
请在 Pinakes 项目中完整执行这篇论文的 ingest，直接完成笔记写入和验证。

源码仓库：<Pinakes 仓库绝对路径>
目标知识库：<vault 绝对路径；默认使用仓库下的 wiki/>
论文：<论文标题 / 链接 / PDF 路径>
研究关注点：<可选；未指定时依据论文和已有笔记，不要替我编造研究目标>

先读取仓库 AGENTS.md、目标目录适用的 agent 约定、docs/maintenance.md 和
docs/wiki-conventions.md，尤其完整执行其中 §6.3–§6.6 与 §7。
项目标准以这些文件为准；不要仅依据这段提示或笔记骨架开始写作。

请把笔记写给“有领域基础、但没有读过这篇论文”的我：
让我知道原方法具体哪里不够、作者为什么这样改、一个样本怎样经过核心流程，
以及哪些实验支持这个设计、还有什么没有解决。易读性与事实准确性同样重要。

先查重并阅读已有笔记，再读原文的方法、实验设置、主要结果、消融、局限和相关附录。
用原文位置核对关键主张，遇到表格或公式提取歧义时查看对应页面。
不要只翻译摘要、罗列模块名或堆公式；关键机制按输入、操作、输出和用途讲清楚，
分开解释训练与推理。适合时用标明“示意”的小例子帮助理解。
结果应说明指标分母、对照条件和结论边界；事实、作者解释、你的推断和我原有的想法要分清。

写入时使用“整体综述 + 论文细节 + 阅读随记”的三层结构，把详细方法和证据组织在论文细节下。
阅读随记是针对这篇论文的个人 Notes，默认留空或保留我原来的理解、疑问和判断，不将论文细节搬入其中。
只有我明确要求时才协助整理个人记录；AI 自行提出的理解或迁移建议明确标为 AI 推断／建议。
小节和篇幅随论文调整，不机械凑章节或字数。已有论文补全原笔记，保留我的批注、
评分、阅读状态、有效链接和关系。不要仅生成骨架，不要因你读过原文而改成“已读”。

完成前按 §6.6 自查内容，再执行 §7 的索引预览与更新、校验、测试和日志。
源码仓库与 vault 不同位置时，工具从源码仓库运行，并使用实际目标 vault；
检查工具是否支持该目标，不把对默认 wiki/ 的测试说成对外部 vault 的验证。
若原文不可得或确有工具阻塞，如实说明未完成部分；不要编造内容或通过结果。
最后简要返回笔记路径、主要补充、实际检查结果与待核实事项。
```

只需重写已有笔记时，把首句改成“请按同样标准重写以下已有论文笔记的综述和论文细节，保留我的阅读随记”，并提供笔记路径。保留用户内容、原文核对和内容自查的要求仍然适用；旧 Notes 的内容需要先辨别，不直接当成个人理解或覆盖。

这套提示明确了过程与验收标准，但不能保证不同模型得到完全相同的理解质量。验收时应看笔记是否讲清实际机制、关键结论是否有依据；篇幅更长或工具校验通过都不能单独说明质量更好。

# 使用指南

想先看看实际操作？从 [实际操作演示](demo.md) 开始。

从一篇论文开始：收好原文，记下关键方法，再把它放到已有的研究方向中。随着笔记积累，Pinakes 的目录树、关系图和阅读看板会成为回看这些工作的入口。

界面跟随 Obsidian 的浅色与深色主题，详情卡、菜单与弹窗采用柔和阴影和半透明层次。弹窗出现与论文切换使用短暂的过渡；启用系统「减少动态效果」后，这些动画会关闭。

安装步骤见 [插件安装说明](../README.md#安装)，需要完整空库时可选用 [研究库安装器](installation.md)。下面的操作使用桌面版 Obsidian。

## 首页

点击左侧 house 图标或执行「打开首页」，进入 Pinakes 首页。首页集中提供刷一刷、关系图谱、添加论文、阅读队列、专题研究、研究想法、论文库及维护工具。「研究想法」对应原有 Ideas 内容。这四个内容入口使用插件原生列表，独立安装也能使用，不要求事先有看板或总览笔记。只有选择「关系图谱」时才打开画布，首页不加载整库图谱。

首页沿用项目主图的共读插画与「让思想，在你与 AI 之间生长。」标题，保持项目介绍和日常使用的视觉一致性。

从首页进入关系图谱时，在当前标签页完整显示，不创建右侧分屏；图谱顶栏「返回首页」也在同一标签页切回首页。

首页展示论文数量与阅读状态，并优先推荐一篇未读论文的综述预览。点击论文标题或「读这一篇」会打开这篇论文的刷一刷弹窗；「换一篇」刷新推荐。每次重新进入首页都会读取最新数据并重置推荐，候选池有多篇时尽量避免连续重复。图谱顶栏的 house 按钮可以返回首页。侧边栏只保留首页入口；刷一刷也可通过命令面板直接打开。

首页可以直接搜索标题、文件名、标签或简介，点击「搜索」后进入论文库并保留关键词。「继续阅读」优先返回最近打开的有效论文，没有历史时提供一篇在读论文。它与随机推荐相互独立，不会把打开过的论文自动标记成已读。

刷一刷记录综述／Notes 阅读区的位置；从「继续阅读」打开时恢复该位置，换篇仍从新论文开头开始。完整 Markdown 笔记会保存 Obsidian 公开的视图状态；该视图提供滚动状态时也会恢复。PDF 阅读位置由 Obsidian 自身管理，Pinakes 不承诺恢复 PDF 页码。最近阅读记录保存在插件设置中，移动论文时会同步路径；已删除论文会跳过。

## 收录论文

**推荐使用 Pinakes「添加论文」作为日常入口。** 随包的 QuickAdd 是可选的模板快捷方式，按需使用即可，具体操作见 [配套插件说明](plugins.md#quickadd可选的模板快捷入口)。

点击左侧 house 图标进入 Pinakes 首页，或在命令面板中搜索「打开首页」。

点击首页「添加论文」，选择本地 PDF。图谱顶栏也保留「添加论文」入口。弹窗会尝试读取标题、作者和摘要，确认年份、文件名与简介后保存。自动提取的结果可能不完整，保存前仍需对照原文。

新论文默认进入「待归档」。每篇论文有自己的文件夹，里面放一份 Markdown 笔记和一份 PDF；导入时复制原文件，源文件保留。

保存完成前表单保持打开，保存时关闭按钮暂不可用。失败后会保留字段，点击「重试导入」继续本次未完成操作；不要改变本次的文件名、PDF 或字段后直接覆盖原目录。成功后提供「打开笔记」和「打开原文 PDF」。快速切换 PDF 或手工改标题时，较早的元数据请求不会覆盖新选择或人工输入。

有未完成操作时，首页会出现「恢复未完成操作」，命令面板也提供同名命令。关系翻转可以恢复原关系；导入文件已齐全时可以完成方向索引更新，也可以撤销本次导入，将新建且未改动的文件夹移入回收站。文件已被修改、包含其他内容或 PDF 校验不一致时会保留文件并提示检查，不自动清理。旧版本未记录的失败目录需要手动确认，不能当作本次导入覆盖。

没有 PDF 时，可以从首页「添加论文」选择先建笔记，也可以右键方向索引新建论文笔记。之后在论文库每行点击「补充 PDF」，或从刷一刷／图谱详情卡点击「补充／替换 PDF」，选文件后自动复制到论文目录、填写 `pdf` 属性并更新原文入口。

替换 PDF 前先备份旧文件和笔记，新文件保留当前关联的文件名，已有引用仍可使用。备份在插件目录 `backups/<操作ID>/` 下；它们保留供恢复，不在论文图谱中展示。属性保存失败时尝试恢复原文件和引用，恢复也失败时可从首页「恢复未完成操作」继续。没有填写 `pdf` 但目录已存在同名文件时不会直接覆盖，请先确认并关联已有 PDF。

## 归档与分类

主方向决定论文放在哪里。读过摘要和方法后，把左侧树中的论文拖到合适的方向索引上；右键「移动到其他方向」也能完成同样的操作。插件会一起移动笔记和 PDF，更新主方向与索引。

一篇论文涉及多个方向时，在详情卡「方向」一行点击 `＋` 添加子方向。子方向保存在笔记属性中，论文仍只有一份。

需要新方向时，右键域索引选择「新建方向索引」。域是 `papers/` 下的一篇索引笔记，它的「方向」小节列出所包含的方向。新建域的格式见 [知识库约定](wiki-conventions.md)。

尚未确定主方向的论文可以继续留在「待归档」。确定方向并移出后，再添加子方向。

新建的空方向可以立即接收第一篇论文；方向身份由实体类型决定，不取决于当前论文数量。

论文列表支持勾选多篇论文归档。点击「选择本页结果」选中当前筛选结果，筛选变化不自动清除已有选择；「取消选择」清空勾选。点击「归档所选论文」先检查论文清单和目标方向，再点「确认归档」。整个论文文件夹、PDF 和附件一起移动，方向字段、两边索引、节点颜色及阅读记录跟随更新。同名冲突不会覆盖，操作逐篇显示成功与失败；移动后字段／索引尚未完成时，可从首页恢复。批量归档不是跨全批次的原子操作，成功论文不会因另一篇失败而回退。

## 原生论文列表

首页「论文库」打开所有论文；「阅读队列」默认显示未读和在读。可以搜索标题、文件名、标签与简介，按年份、状态、方向、重要度或标签过滤，并按年份、重要度或标题排序。每行展示论文标题和简介，可直接打开笔记、进入刷一刷、打开已有 PDF 或修改阅读状态。结果和状态来自同一份 Markdown。

列表再次打开或刷新时保留当前筛选条件；首页新搜索会以新的关键词进入。每行提供「补充／替换 PDF」；「继续阅读」入口只保留在首页。

「专题研究」「研究想法」也提供原生列表。没有内容时可以直接「新建专题」或「记录想法」，填写名称后创建并打开笔记；不要求用户先手工创建总览。配套 Dataview 看板仍可使用，但不是这些入口的依赖。

## 阅读与记录

点击已选中的论文行，或在详情卡中选择「打开笔记」。笔记开头的原文链接可以在侧栏打开 PDF，便于边读边记。

正文可以按论文组织。通常先写清它解决的问题和核心方法，再记录值得回看的推导、实验或限制。模板里的章节可以增删。

详情卡和 Obsidian 属性面板都能修改阅读状态、重要度和标签：

| 属性 | 用途 |
| --- | --- |
| 阅读状态 | `未读`、`在读`、`已读`、`精读`；也可以添加自定义状态 |
| 重要度 | 1–5，数值越大，图上的节点越大 |
| 标签 | 标记具体方法，例如 `semantic-id`、`codebook`；每篇建议 2–4 个 |

标签的完整词表在 [tag_vocabulary.yml](../tools/tag_vocabulary.yml)。新标签需要登记进词表，命令行校验才会识别。

`_dashboards/reading-queue.md` 按阅读状态整理队列，未读论文按重要度排序。其他看板可以查看全部论文、按方向浏览，或找出待补元数据的笔记。看板在 Obsidian 中由 Dataview 渲染。

## 刷一刷论文

点击首页推荐卡的标题或「读这一篇」，或在命令面板执行「Pinakes: 刷一刷论文」，打开独立阅读弹窗。图谱顶栏也保留刷一刷入口。

每次优先从未读论文中随机抽取一篇；缺少阅读状态按未读处理。没有未读论文时，优先抽取未设置重要度的论文；都有评分时，从全部论文随机抽取。重要度 `1` 也算已设置。当前候选池有多篇时，尽量不连续刷到同一篇。

弹窗以阅读为主，只展示笔记中的「整体综述」与「Notes」两个章节；「我的批注」「我的批注与 Open debates」「个人笔记」「我的笔记」「阅读笔记」也作为 Notes 识别，保留原章节标题。章节内的小标题一并显示，其他方法、实验、路径等内容通过「打开笔记」查看。缺少章节时显示提示，仅浏览不会自动补建内容。

标题与作者在阅读区顶部，正文自然排版，整篇阅读区统一滚动。阅读状态、重要度与「再刷一篇」固定在底部，状态按钮直接保存；仅浏览不会改变阅读状态。「编辑内容」可以分别修改综述和 Notes，保存时只更新对应章节；原有属性、简介、关系和其他章节保持原样。缺少章节时主动填写内容，会在原笔记中添加该章节。

点击「再刷一篇」、打开笔记、进入图谱或关闭弹窗前，会先保存编辑内容。如果同一章节已被其他编辑器修改，弹窗会提示冲突并保留输入；先复制需要保留的修改，再在编辑模式中点击「重新载入」读取最新笔记，该按钮会放弃当前未保存的内容。「放弃修改」也可以取消未保存的编辑，包括原笔记已被删除、无法重新载入的情况。笔记有多个同名章节时，请打开完整笔记编辑，避免修改错误的章节。

## 浏览关系图

点击索引节点，画布展示它的子树及相关论文；点击论文节点，画布展示这篇论文、直接关联的节点，以及这些节点之间已有的关系。树外的关联论文会显示为较淡的小点，悬停可以查看名称。

节点填充颜色表示方向，大小表示重要度。阅读状态显示在树和详情卡中。图例可以开关不同类型的连线；拖动画布平移，滚轮缩放，顶栏「适配视图」可以重新容纳当前子图。

论文之间有四类关系：

| 类型 | 含义 |
| --- | --- |
| `extends` | 在另一篇工作的技术路线上继续改进或扩展 |
| `uses` | 复用另一篇工作的具体模块、损失函数或数据构造 |
| `competes` | 用另一条路线解决同一个问题，可以作为对比基线 |
| `contradicts` | 在可比较的条件下，对同一问题给出相反结论 |

点击顶栏铅笔进入编辑模式，依次点击两个节点，再选择关系类型。`extends` 和 `uses` 从后来采用或改进方法的论文指向被采用的工作。点击已有关系边可以修改类型、翻转有向边或删除。

关系翻转先写入反向关系，再移除原关系。第二步失败时恢复原关系；如果恢复也失败，会显示未完成状态并保留操作记录，点击首页「恢复未完成操作」重试。恢复只处理这条关系，不覆盖正文和其他属性。

普通引用使用「默认链接」，保存到正文中。带类型的关系保存到笔记属性中；每条关系都应有原文依据，判据见 [关系字段](wiki-conventions.md#31-关系字段)。

## 专题与想法

需要把多篇论文放在一起比较时，在 `deep-research/` 下建专题目录，用 `【Deep Research】<专题>.md` 作为主文档，并链接到论文库中的笔记。

自己的方案、证据底稿和实验计划放在 `ideas/`。每个方案包有一篇索引笔记，方案稿以 `【idea】` 开头，进度用 `stage` 记录：待做、在做、已成稿、已投稿、已发表或废弃。

专题和想法可以关联库中的论文，也可以用 `locator` 引用外部资源。引用资源的格式与当前支持范围见 [实体模型](entity-model.md)。

## 与 AI 协作

让能读写本地文件、阅读 PDF 的 agent 从本项目源码仓库根目录工作，并读取 `AGENTS.md`。之后只需给它一句话：

```text
ingest /path/to/paper.pdf
```

也可以把 PDF 路径换成论文标题或 arXiv 链接。agent 会按 [录入流程](wiki-conventions.md#7-录入流程) 查重、阅读原文、补全笔记、维护索引并校验。已经通过 Pinakes「添加论文」导入的论文会在已有笔记上补全；你写下的批注与想法应予保留。

你可以随时直接修改笔记，或请 AI「结合我在笔记中的疑问，补充方法的适用条件」。原文结论、AI 推断和你的研究判断应分别写清楚，让后续阅读有据可查。

`ingest` 是外部 agent 的任务约定，插件本身不调用模型。仅安装插件或完整库模板时，还需要将本源码仓库提供给 agent，才能使用这里的规范和 Python 工具；安装包目前不附带这些工具。

Python 工具需要安装仓库中的依赖：

```bash
python3 -m pip install -r requirements.txt
```

agent 可以用 `python3 tools/pinakes.py describe --json` 查看实体类型、字段和资源边界。笔记写完后运行：

```bash
python3 tools/research_wiki.py rebuild-index wiki/ --apply
python3 tools/lint.py --wiki-dir wiki/
```

如果知识库安装在其他位置，把上面的 `wiki/` 换成该目录。完整命令见 [工具手册](tools.md)。

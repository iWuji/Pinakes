# 使用指南

从一篇论文开始：收好原文，记下关键方法，再把它放到已有的研究方向中。随着笔记积累，Pinakes 的目录树、关系图和阅读看板会成为回看这些工作的入口。

安装步骤见 [插件安装说明](../README.md#安装)，需要完整空库时可选用 [研究库安装器](installation.md)。下面的操作使用桌面版 Obsidian。

## 收录论文

**推荐使用 Pinakes「添加论文」作为日常入口。** 随包的 QuickAdd 是可选的模板快捷方式，按需使用即可，具体操作见 [配套插件说明](plugins.md#quickadd可选的模板快捷入口)。

打开知识库中的 `【索引】研究总览.md`，点击左侧的 network 图标进入 Pinakes。也可以在命令面板中搜索「打开关系图谱」。

点击图谱顶栏的「添加论文」，选择本地 PDF。弹窗会尝试读取标题、作者和摘要，确认年份、文件名与简介后保存。自动提取的结果可能不完整，保存前仍需对照原文。

新论文默认进入「待归档」。每篇论文有自己的文件夹，里面放一份 Markdown 笔记和一份 PDF；导入时复制原文件，源文件保留。

没有 PDF 时，可以从欢迎页的「新建第一篇论文」跳过选文件，也可以右键方向索引新建论文笔记。之后把 PDF 放进论文文件夹，再补上笔记的 `pdf` 属性和原文链接。

## 归档与分类

主方向决定论文放在哪里。读过摘要和方法后，把左侧树中的论文拖到合适的方向索引上；右键「移动到其他方向」也能完成同样的操作。插件会一起移动笔记和 PDF，更新主方向与索引。

一篇论文涉及多个方向时，在详情卡「方向」一行点击 `＋` 添加子方向。子方向保存在笔记属性中，论文仍只有一份。

需要新方向时，右键域索引选择「新建方向索引」。域是 `papers/` 下的一篇索引笔记，它的「方向」小节列出所包含的方向。新建域的格式见 [知识库约定](wiki-conventions.md)。

尚未确定主方向的论文可以继续留在「待归档」。确定方向并移出后，再添加子方向。

## 阅读与记录

点击已选中的论文行，或在详情卡中选择「打开笔记」。笔记开头的原文链接可以在侧栏打开 PDF，便于边读边记。

正文可以按论文组织。通常先写清它解决的问题和核心方法，再记录值得回看的推导、实验或限制。模板里的章节可以增删。

详情卡和 Obsidian 属性面板都能修改阅读状态、重要度和标签：

| 属性 | 用途 |
| --- | --- |
| 阅读状态 | `未读`、`在读`、`已读`、`精读`；也可以添加自定义状态 |
| 重要度 | 1–5，数值越大，图上的节点越大 |
| 标签 | 标记具体方法，例如 `semantic-id`、`codebook`；每篇建议 2–4 个 |

标签的完整词表在 [tag_vocabulary.yml](../tools/tag_vocabulary.yml)。新标签需要登记进词表，命令行校验才会识别。

`_dashboards/reading-queue.md` 按阅读状态整理队列，未读论文按重要度排序。其他看板可以查看全部论文、按方向浏览，或找出待补元数据的笔记。看板在 Obsidian 中由 Dataview 渲染。

## 浏览关系图

点击索引节点，画布展示它的子树及相关论文；点击论文节点，画布展示这篇论文、直接关联的节点，以及这些节点之间已有的关系。树外的关联论文会显示为较淡的小点，悬停可以查看名称。

节点填充颜色表示方向，大小表示重要度。阅读状态显示在树和详情卡中。图例可以开关不同类型的连线；拖动画布平移，滚轮缩放，顶栏「适配视图」可以重新容纳当前子图。

论文之间有四类关系：

| 类型 | 含义 |
| --- | --- |
| `extends` | 在另一篇工作的技术路线上继续改进或扩展 |
| `uses` | 复用另一篇工作的具体模块、损失函数或数据构造 |
| `competes` | 用另一条路线解决同一个问题，可以作为对比基线 |
| `contradicts` | 在可比较的条件下，对同一问题给出相反结论 |

点击顶栏铅笔进入编辑模式，依次点击两个节点，再选择关系类型。`extends` 和 `uses` 从后来采用或改进方法的论文指向被采用的工作。点击已有关系边可以修改类型、翻转有向边或删除。

普通引用使用「默认链接」，保存到正文中。带类型的关系保存到笔记属性中；每条关系都应有原文依据，判据见 [关系字段](wiki-conventions.md#31-关系字段)。

## 专题与想法

需要把多篇论文放在一起比较时，在 `deep-research/` 下建专题目录，用 `【Deep Research】<专题>.md` 作为主文档，并链接到论文库中的笔记。

自己的方案、证据底稿和实验计划放在 `ideas/`。每个方案包有一篇索引笔记，方案稿以 `【idea】` 开头，进度用 `stage` 记录：待做、在做、已成稿、已投稿、已发表或废弃。

专题和想法可以关联库中的论文，也可以用 `locator` 引用外部资源。引用资源的格式与当前支持范围见 [实体模型](entity-model.md)。

## 与 AI 协作

让能读写本地文件、阅读 PDF 的 agent 从本项目源码仓库根目录工作，并读取 `AGENTS.md`。之后只需给它一句话：

```text
ingest /path/to/paper.pdf
```

也可以把 PDF 路径换成论文标题或 arXiv 链接。agent 会按 [录入流程](wiki-conventions.md#7-录入流程) 查重、阅读原文、补全笔记、维护索引并校验。已经通过 Pinakes「添加论文」导入的论文会在已有笔记上补全；你写下的批注与想法应予保留。

你可以随时直接修改笔记，或请 AI「结合我在笔记中的疑问，补充方法的适用条件」。原文结论、AI 推断和你的研究判断应分别写清楚，让后续阅读有据可查。

`ingest` 是外部 agent 的任务约定，插件本身不调用模型。仅安装插件或完整库模板时，还需要将本源码仓库提供给 agent，才能使用这里的规范和 Python 工具；安装包目前不附带这些工具。

Python 工具需要安装仓库中的依赖：

```bash
python3 -m pip install -r requirements.txt
```

agent 可以用 `python3 tools/pinakes.py describe --json` 查看实体类型、字段和资源边界。笔记写完后运行：

```bash
python3 tools/research_wiki.py rebuild-index wiki/ --apply
python3 tools/lint.py --wiki-dir wiki/
```

如果知识库安装在其他位置，把上面的 `wiki/` 换成该目录。完整命令见 [工具手册](tools.md)。

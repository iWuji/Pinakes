# 界面文案约定

Pinakes 的声音像一起读论文的同伴：自然、简短，说清楚接下来可以做什么。首页可以带一点温度，日常操作直接，失败与删除提示准确。避免把每句话写成口号，也不使用刻意卖萌、催促或夸张的成功提示。

## 写作原则

- 先说用户关心的事。按钮写动作，说明写结果。例如「添加论文」「读这一篇」「换一篇」。
- 一句话解决一个问题。输入提示提供真实例子，少用括号堆叠说明。
- 同一概念使用同一名称，不在不同页面混用「重要」「重要性」「评分」。
- 正常操作不展示实现细节。frontmatter、schema、slug、locator 等名称只在编辑对应属性或维护工具时解释。
- 空状态说明当前缺什么，并给出一个可行的入口。没有资料时不暗示已经生成内容。
- 保存失败和冲突说明内容是否已保存或保留，再给下一步。只有能确认的状态才写「已保存」。
- 删除、覆盖、重新读取等操作明确说明影响；不以「先逛逛」等轻松说法代替破坏性操作。
- 控件和短标签不加句号，完整说明使用中文标点。成功提示简短，不反复使用感叹号。

## 名称

| 场景 | 名称 | 说明 |
| --- | --- | --- |
| 默认入口 | 首页 | 不称资源管理器或工作台 |
| 论文关联视图 | 关系图谱 | 直接入口写「打开关系图谱」 |
| 随机阅读 | 刷一刷 | 继续抽取写「再刷一篇」，首页替换推荐写「换一篇」 |
| 打开首页推荐 | 读这一篇 | 点击后与推荐卡是同一篇 |
| 导入或新建 | 添加论文 | 提交时可以用「创建」；未导入 PDF 的内容称「笔记」 |
| 阅读进度 | 阅读状态 | 属性值仍为未读、在读、已读、精读 |
| 重要程度 | 重要度 | frontmatter 字段仍为 importance，取值仍为 1–5 |
| 英文磁盘标识 | 文件名 | 输入例子为 my-paper；需要说明属性时注明 slug |
| 本地个人内容入口 | 研究想法 | 对应原有 Ideas 内容，不改笔记标题或路径 |
| 全部论文看板入口 | 论文库 | 浏览全部已收录论文 |
| 机器可读描述 | 查看库结构 | 内容仍可复制为 JSON |
| 外部资源状态 | 检查资源 | 不把未探测的远程地址写成已验证可用 |

「整体综述」与 Notes 展示笔记原有章节名。论文英文标题、关系字段 extends / uses / competes / contradicts、用户自定义状态和标签保留原值；文案调整不改知识内容或数据格式。

## 示例

首页延续 README 和主图的品牌表达：「让思想，在你与 AI 之间生长。」「人读得懂，AI 接得上。」；副文案承接它，例如「一起读论文、写笔记，让每次思考都有迹可循。」。主图以 docs/pinakes-cover.svg 为真源，首页使用其中的共读插画。功能卡片直接说明各入口能做什么，避免每个入口都重复口号或使用「看看」「慢慢」「一点」等泛化表达。

| 原表达 | 推荐表达 |
| --- | --- |
| 英文机器 id(kebab-case)，决定文件夹名 | 文件名：如 my-paper，用小写英文和短横线 |
| 第一次建：没有 PDF 也行，先建笔记骨架 | 有 PDF 就选一份，没有也可以先建笔记，之后再补 |
| 描述库结构（describe --json） | 查看库结构 |
| 有未保存的修改；再刷一篇或关闭前会先保存 | 修改还没保存，换篇或关闭时会自动保存 |
| 暂时无相关实例 | 还没有收录论文，先在首页添加一篇 |

## 参考与技能选择

参考 Apple Human Interface Guidelines 的 Writing（熟悉词汇、统一术语、按场景调整语气）与 Microsoft Writing Style Guide / Windows Writing style（简单、人性化、明确动作、准确错误提示）。具体中文措辞以本项目的使用场景为准，不逐句翻译英文指南。

2026-11-18 使用 OxygenSkills 搜索 ux writing、copywriting 和文案。未找到专门的 UX Writing 技能；搜索到的 copywriting 为营销文案用途，不能据此当作产品界面文案规范。此次未安装额外技能。

后续审查重点：按钮是否说明动作，名称是否一致，说明是否能删短，失败提示是否提供真实可行的下一步。变更后核对相关测试与真实界面布局。
